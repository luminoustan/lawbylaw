## 2. Copyleft findings

### 2.1 Application code (Rust + npm) — CLEAN

- **Rust (329 crates):** all permissive (MIT / Apache-2.0 / BSD / ISC / Zlib /
  BSL-1.0 / Unicode-3.0 / Unlicense / CC0 / CDLA-Permissive-2.0).
  - One crate, `r-efi 6.0.0`, is `MIT OR Apache-2.0 OR LGPL-2.1-or-later` — an
    **OR** choice, so the permissive MIT/Apache option is selected. No copyleft
    obligation. It is a target-specific dependency of `getrandom` for UEFI only:
    `cargo tree -i r-efi --target x86_64-unknown-linux-musl` reports "nothing to
    print", so it is **not compiled into the binary** (confirmed: 0 `r-efi`
    symbols in the release binary). It appears in `Cargo.lock` only because the
    lockfile records dependencies for all target platforms.
- **npm (194 packages):** all permissive except `caniuse-lite` (`CC-BY-4.0`),
  a **dev-only** transitive dependency of `vite-plugin-solid` → Babel →
  `browserslist`. It is not copyleft (CC-BY-4.0 is permissive-with-attribution),
  is never installed in the runtime image, and does not appear in the built
  `dist/` output. It cannot be removed without dropping `vite-plugin-solid`.

**No GPL/AGPL/LGPL/MPL code is compiled into or bundled with the application.**

### 2.1.1 Added 2026-10-15: Qwen3 token counting

`get_section` now counts Qwen3 tokens in the server (the vector collections are
chunked by that tokenizer). This adds:

- **`tokenizers` 0.21** (Apache-2.0) built with `default-features = false` and
  `features = ["fancy-regex"]`, so it is pure Rust (no `onig` C code) and still
  links statically on musl. 37 transitive crates were added; all are permissive
  (MIT / Apache-2.0 / Zlib / BSD-2-Clause, as OR choices where dual-licensed).
  No copyleft crate is compiled in.
- **The Qwen3-Embedding-0.6B vocabulary** (Apache-2.0, from Hugging Face
  `Qwen/Qwen3-Embedding-0.6B`) is **not vendored**. `make tokenizer` downloads it
  into `server/data/qwen3_tokenizer.json` (git-ignored) and the server loads it
  at startup from `TOKENIZER_PATH` (default `data/qwen3_tokenizer.json`). The
  file contains no executable code and no model weights. Because it is not part
  of this repository, and a default image build does not include it, no
  third-party data licence obligation attaches to what is distributed here.
  Without it the server logs a warning and estimates 2 chars/token.

### 2.2 Container base image — now `scratch` (zero copyleft)

The runtime image is built `FROM scratch` and contains **no OS packages at all**.
The server is a fully static musl binary, so there is no libc, no shell and no
Debian utilities in the image. The SBOM therefore has **zero copyleft entries**.

The binary has **no dynamic dependencies** (verified with `objdump -p`):

```
$ objdump -p lawbylaw-server | grep NEEDED
(no dynamic NEEDED - fully static)
$ ldd lawbylaw-server
statically linked
```

**Conclusion: no copyleft obligation attaches to the lawbylaw application or its
image.** (For the record, the previous Debian-based image was also legally fine:
its GPL/LGPL packages were separate co-installed programs, glibc's LGPL permits
dynamic linking, and `libgcc_s` carries the GCC Runtime Library Exception. The
switch to scratch removes the copyleft entries from the SBOM entirely.)

## 3. Build defect found and fixed

The original release binary linked `libssl.so.3` / `libcrypto.so.3` (pulled in
via `reqwest`'s default `native-tls` feature), but the runtime stage of
`Containerfile` installed only `ca-certificates` — **`libssl3` was missing**, so
the image failed to start:

```
$ podman run --rm -v .../lawbylaw-server:/app/bin:ro debian:bookworm-slim /app/bin
/app/bin: error while loading shared libraries: libssl.so.3: cannot open shared object file
```

**Fixed** by switching `reqwest` to rustls and building a static musl binary
(see §4). OpenSSL is no longer linked at all.

## 4. Zero-copyleft image — APPLIED

The change is now permanent in the repo:

1. `server/Cargo.toml` — `reqwest` uses rustls, not native-tls/OpenSSL:
   ```toml
   reqwest = { version = "0.12", default-features = false, features = ["json", "stream", "rustls-tls"] }
   ```
2. `Containerfile` — the `server` stage installs `musl-tools`, adds the
   `x86_64-unknown-linux-musl` target and builds with
   `RUSTFLAGS="-C target-feature=+crt-static"`; the runtime stage is
   `FROM scratch`, copying in the binary, `data/`, `dist/` and the CA roots.
3. `Makefile` — `make server-build-static` reproduces the image binary;
   `make server-build` still produces the debug binary the eval suite uses.

Result: a **~19 MB image with zero packages and zero copyleft**, verified by
running it and hitting `GET /api/health` -> `{"status":"ok"}` and a real
`POST /api/chat` (which exercises the outbound HTTPS/CA-cert path).

### Image size

| Image | Base | Size |
|-------|------|-----:|
| Before | `debian:bookworm-slim` | 107 MB |
| After | `scratch` | 19.3 MB |

~82% smaller. The old image was dominated by the Debian base (77.9 MB) plus the
dynamically-linked binary; the new one is just the static binary (18.7 MB) and
the web assets (289 kB), CA roots (228 kB) and `data/` (99 kB). The build stages
(`rust:1-bookworm` 1.6 GB, `node:22-bookworm-slim` 232 MB) are discarded.

Trade-offs: no shell/package manager in the image (debug via `podman logs`), and
CA certificates must be copied in from the build stage (done in the Containerfile).

## 5. Recommendations

1. Regenerate `sbom.cdx.json` with `python3 scripts/gen_sbom.py` on every
   dependency change (the script exits non-zero if a licence cannot be resolved).
2. Add a CI license gate that fails on strong copyleft in the Rust/npm trees
   (currently clean, so this is a guardrail, not a fix).
