# Security notes

- No accounts, cookies, database or server-side chat history. Chats live only in the visitor's browser (IndexedDB). This is not anonymity: the free path sends the conversation to Nebius Token Factory, the BYOK path sends it to Nebius or DeepSeek, and provider retention and training terms apply. The server also processes IP addresses for rate limits.
- The only API routes are `POST /api/chat`, `GET /api/agent`, `POST /api/tool`, `POST /api/cite`, `POST /api/links`, `GET /api/limits`, `GET /api/health`. Everything else under `/api` and `/admin` returns 404 (asserted by tests).
- `POST /api/tool` runs one stateless tool call (corpus search, section/judgment read, Tavily search) for browsers that run the model loop themselves with their own key. It takes no LLM key, never calls an LLM, remembers nothing between calls, only runs a fixed allowlist of tools per context, and has its own per-IP rate and in-flight limits (`LIMIT_TOOL_*`). Failures return a fixed message, never upstream details. `GET /api/agent` hands such a browser the prompts, tool definitions and tuning numbers (public, nothing caller-specific, no secrets), so the browser loop and the server loop cannot drift. `POST /api/links` returns the Singapore Statutes Online links for the Acts a piece of answer text names (the act index lives on the server; pure function, same limiter). `POST /api/cite` is the companion of `/api/tool`: it resolves a research agent's references to the exact corpus text (sections sent by the client are used as given; anything else is looked up in Qdrant), shares the same limiter, and resolves at most 60 references per call.
- **Your own API key (optional).** A user can paste a Nebius or DeepSeek key in Settings. It is kept only in that browser (`localStorage` for "remember on this device", `sessionStorage` otherwise, memory if the browser blocks both), under its own entry apart from the chat database, and is removed by "Delete all my chats, settings and API key". The model loop then runs in the browser and calls the provider directly; the key goes only into the `Authorization` header of a request to that provider's fixed URL (no free-text URL or model), with no cookies and no referrer, and is never sent to this server, so it cannot appear in its logs. The CSP `connect-src` allows exactly this site those two provider origins (a Rust test keeps it equal to the presets in `web/src/agent/providers.ts`) and `https://api.tavily.com` (a test keeps it equal to `TAVILY_URL` in `web/src/agent/tavily.ts`), so a tampered page still cannot send a key elsewhere. This site still receives the legal-database searches the assistant makes and the answer text (for links), and keeps neither. What the provider says when it rejects a request is shown to the user (read with a size and time cap, reduced to one plain line, the key redacted if echoed, rendered as text). Limits: anything running on the page (a malicious extension, or an XSS bug) can read browser storage; the CSP guards against the latter, and "session only" exists for the former. A visitor's own Tavily search key follows the same rules (own storage entry, never shown after saving, never sent to this server, `Authorization` header of a request to `api.tavily.com` only, no cookies, no referrer) and is used only when the browser runs the loop; the Playwright eval checks that it never appears in any request to this site or to the model provider. `evals/byok-browser.e2e.mjs` checks all of this live in a real browser.
- **Turnstile session gate.** With `TURNSTILE_ENFORCE=true` the expensive routes need a short-lived HMAC-signed session token in `x-lbl-session`, obtained by solving Cloudflare Turnstile (`/api/session`, rate limited per IP). Tokens are stateless and held in page memory only. The CSP allows `https://challenges.cloudflare.com` for `script-src` and `frame-src` only. Per-IP limits key on the IPv6 /64 and the tracked-address table is bounded (new addresses are refused past the ceiling).
- All limits are enforced server-side per request; see `GET /api/limits` and `evals/report.md`.
- Secrets: only in environment variables. `.env` is git-ignored; CI runs a secret scan (`.gitleaks.toml`).
- No secret values are committed. `.env.example` lists variable names only; real values come from the environment or a secret store.
- **Rotate any key that was ever pasted into a chat, terminal output or transcript.**
- Behind a proxy, set `TRUST_PROXY` to `cf` or `xff` only when that proxy overwrites the header; otherwise client IPs can be spoofed.
- In-memory limiters are per replica. Use an edge rate limit (e.g. Cloudflare) for multi-replica deployments.
